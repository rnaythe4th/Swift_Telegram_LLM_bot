# Рост и монетизация бота — стратегия и план внедрения

> Документ-инструкция для владельца. Цель: превратить бота в источник дохода —
> заинтересовать пользователей, удержать их и довести до покупки.
> Написано с расчётом, что опыта в growth/маркетинге нет: сначала объясняется
> «почему», затем «что делать» и «где в коде».
>
> Это план. Пункты помечены приоритетами **P0 / P1 / P2**. Выполнять сверху вниз.
> Когда будешь готов — попроси реализовать конкретный пункт по номеру.

## 0. Как вообще работают деньги в боте (ликбез на 3 минуты)

Любой продукт с подпиской проходит через воронку из 5 шагов (её называют «пиратские
метрики», AARRR). Деньги теряются на каждом стыке:

```
1. ПРИВЛЕЧЕНИЕ   — человек нажал /start
        ↓ (сколько доходит до первого сообщения?)
2. АКТИВАЦИЯ      — отправил первое сообщение, увидел ценность («ага, работает!»)
        ↓ (сколько вернулось на следующий день?)
3. УДЕРЖАНИЕ      — пользуется регулярно, привык
        ↓ (сколько упёрлось в потолок бесплатного?)
4. ВЫРУЧКА        — заплатил
        ↓ (сколько продлило / привело друзей?)
5. РЕФЕРАЛЫ       — привёл друга, продлил подписку
```

**Главный закон freemium:** платят только тогда, когда бесплатная версия
одновременно (а) даёт реальную пользу — иначе человек уходит, и (б) имеет
ощутимый потолок, который снимается за деньги — иначе незачем платить.

Сейчас у бота **есть польза, но почти нет потолка**: бесплатные модели работают
без ограничений. Единственный триггер к покупке — попытка включить платную модель
(бот молча переключает на бесплатную) и редкая реклама. Это самая дырявая часть
воронки, и именно её надо чинить в первую очередь.

**Ориентир по конверсии:** в consumer-freemium нормой считается **2–5%**
из активных бесплатных в платящих. Если сейчас околонуля — почти любой из P0-пунктов
ниже даёт кратный рост. Не гонись за идеалом — гонись за первым платящим,
потом за десятым.

## 1. Диагностика: где протекает воронка прямо сейчас

| Шаг воронки | Что есть сейчас | Дыра |
|---|---|---|
| Привлечение | `/start` с приветствием (`BotCommandHandler.sendStartGreeting`) | Нет реферального цикла для обычных юзеров. Приглашения (`handleInviteRedemption`) — только раздача админской лицензии, не вирусный рост. |
| Активация | Приветствие + кнопки «Меню/Инструкция» | Нет мгновенной демонстрации ценности: ни примеров запросов, ни «попробуй спросить…». Пустой чат = риск ухода. |
| Удержание | Free-модели без лимита, память чата, мультимодальность | Удержание ок. Но нет причины возвращаться каждый день (нет привычки к «премиум-вкусу»). |
| Потолок → покупка | Платная модель → авто-переключение на бесплатную + приписка `/buy` (`GenerationCoordinator.processContent:141-159`) | Нет пробы премиума. Юзер никогда не почувствовал разницу GPT/Claude/Gemini → не знает, за что платить. Потолок «невидимый». |
| Оплата | Подписка 30 дней через Stars/крипту/карту (`handleBuyAction`, `BotMenuHandler:1845`) | Оффер сформулирован по-B2B: «персональная копия бота, свои чаты и пользователи». Обычному юзеру непонятно. Нет анкоринга цены, нет срочности. |
| Баланс (pay-as-you-go) | Механика полностью готова: биллинг за сообщение, наценка 30%, остаток в футере | **Юзер не может пополнить сам** — только админ через `/balance add` (`BotCommandHandler:503`). Целый способ монетизации выключен для самообслуживания. |
| Реферал / продление | Подписка продлевается вручную через `/buy` | Нет напоминания перед истечением, нет winback после, нет награды за друга. Отток невидим и не отрабатывается. |
| Аналитика | `/metrics`: рантайм-счётчики. Супер-меню: токены/стоимость по тенантам | Нет воронки: сколько нажали /start → написали → упёрлись → купили. Владелец не видит, где теряет деньги. |

**Вывод:** продукт крепкий, воронка — дырявая на трёх стыках: *активация*,
*невидимый потолок*, *оплата (упаковка + самообслуживание)*.

## 2. Решение №1, которое надо принять до кода: кто твой клиент?

Сейчас бот обслуживает две разные аудитории одним оффером, и это размывает
сообщение. Их надо разделить:

- **Персона A — обычный пользователь (B2C).** Хочет «умный ИИ в телеге: без
  рекламы, без лимитов, лучшие модели». Массовый, дешёвый чек, ставка на объём
  и конверсию. **Это путь к «юзеры заинтересованы и покупают».**
- **Персона B — реселлер/владелец сообщества (B2B).** Хочет «свою копию бота»
  для своей группы/канала: свои дефолты, пресеты, управление доступом чатов.
  Их мало, чек выше.

**Рекомендация:** вести маркетинг и paywall под **персону A** (объём + конверсия),
а «свою копию бота» оставить как **старший тариф/апселл** для тех, кому это нужно.
Технически всё уже есть — надо только развести тексты и упаковку тарифов.

> ⚠️ Это развилка. Весь копирайтинг ниже написан под персону A. Если хочешь вести
> под B2B — скажи, перепишу приоритеты и тексты. По умолчанию идём в B2C.

## 3. Приоритизированный роадмап

Каждый пункт: **что / зачем (принцип) / где в коде / трудоёмкость / риск**.
Трудоёмкость грубая: S = часы, M = день, L = несколько дней.

### P0 — сделать в первую очередь (максимум денег на единицу усилий)

#### P0.1 — Самостоятельное пополнение баланса («пакеты кредитов»)
- **Что:** дать юзеру купить кредиты ($2 / $5 / $10) прямо в боте через Stars/крипту/карту
  и тратить их на любые модели по факту (per-message), без подписки.
- **Зачем (принцип: снизить порог первой оплаты).** Подписка — это обязательство
  «на месяц вперёд». Кредиты — это «попробовать за $2». Низкий порог = больше первых
  платежей, а первый платёж — самый трудный. Дальше часть перейдёт на подписку.
- **Почему это первый пункт:** вся дорогая механика уже написана — биллинг за
  сообщение, наценка `priceMultiplier()`, списание, показ остатка в футере,
  `creditBalance()` (`ChatContextStore:1822`). **Не хватает только кнопок покупки и
  зачисления после оплаты.** Максимальная отдача за минимум кода.
- **Где в коде:**
  - `BotMenuHandler.handleBuyAction` (~`:1845`) — добавить `buy:credits:<pack>` и
    отправку `sendInvoice` с payload вида `credits_<cents>`.
  - Страница «💳 Полный доступ» (`renderBuy`, ~`:1790-1840`) — добавить блок
    «Или пополнить баланс: [$2] [$5] [$10]».
  - `BotOrchestrator.handleSuccessfulPayment` (`:396`) — читать `invoice_payload`
    (уже приходит, `TelegramSuccessfulPayment.invoice_payload:167`). Если начинается
    с `credits_` → вызвать `creditBalance()` вместо `activatePaidSubscription()`.
  - `pre_checkout_query` валидация цены (`BotOrchestrator:341`) — научить пропускать
    credit-payload (сейчас проверяет цену подписки).
  - Крипта: `CryptoPaymentService` создаёт инвойс под подписку — для кредитов нужна
    ветка «зачислить на баланс», либо на старте разрешить кредиты только Stars/картой
    (проще), крипту добавить позже.
- **Трудоёмкость:** M (Stars+карта). Крипта-кредиты — ещё +M, можно отложить.
- **Риск:** низкий. Не ломает существующий флоу подписки (ветвление по payload).

#### P0.2 — «Премиум-вкус»: N бесплатных премиум-сообщений в день
- **Что:** бесплатному юзеру давать, например, **5 сообщений в день на платных
  моделях** (GPT/Claude/Gemini). Исчерпал — «на сегодня премиум закончился,
  продолжай на бесплатной или открой безлимит: /buy». Сбрасывается каждый день.
- **Зачем (принцип: сначала дай попробовать вкус, потом покажи потолок).**
  Нельзя продать то, что человек не пробовал. Сейчас юзер **никогда** не видел
  разницу между бесплатной и топовой моделью → платить не за что. Дневная порция
  премиума решает сразу два шага воронки: **удержание** (повод вернуться завтра за
  новой порцией → привычка) и **конверсию** (регулярно упирается в потолок → покупает).
- **Почему именно дневная порция, а не разовый триал:** разовый триал заканчивается
  один раз и забывается. Дневной лимит создаёт **повторяющийся** момент желания —
  каждый день напоминает, что за деньги лимита нет.
- **Где в коде:**
  - Новый счётчик в `ChatContextStore`: `[userID: (day: Date, premiumUsed: Int)]`.
    **Важно (§17 CLAUDE.md):** любая новая изменяемая сущность обязана (а) помечать
    dirty-set при мутации, (б) экспортироваться/импортироваться в
    `ChatContextStore+Persistence.swift`, иначе не сохранится. Либо — если лимит
    дневной и потеря при рестарте некритична — держать в памяти без персиста
    (проще, дешевле; счётчик просто обнулится при рестарте — не страшно).
  - Гейт в `GenerationCoordinator.processContent` (`:141-159`): сейчас при отсутствии
    полного доступа платная модель **молча заменяется** на бесплатную. Заменить логику:
    если есть остаток дневного премиума и юзер сам выбрал платную модель — разрешить и
    списать из дневного лимита; если исчерпан — тогда переключать + показывать оффер.
  - Оффер при исчерпании — с inline-кнопкой «⚡ Открыть безлимит» → сразу на paywall.
- **Трудоёмкость:** M.
- **Риск:** средний — не переборщи со щедростью (5/день — старт, крути позже).
  Free-модели оставить **безлимитными** (это удержание), лимитировать только премиум.

#### P0.3 — Переписать paywall под пользу и с анкорингом
- **Что:** переписать страницу покупки и описания инвойсов с языка «персональная
  копия бота» на язык выгод обычного юзера + добавить ценовой анкоринг.
- **Зачем (принцип: продавай результат, не фичи; анкоринг).** «Персональная копия
  бота» — это про механику, а не про выгоду. Человек покупает **исход**: «умный ИИ,
  без рекламы, без лимитов». Анкоринг: рядом с ценой показать, с чем сравнить
  (напр., «дешевле одной чашки кофе», или годовой тариф рядом с месячным — тогда
  месячный выглядит выгодно).
- **Где в коде:** `renderBuy` (`BotMenuHandler:1790-1840`), описания в `sendInvoice`
  (`:1871-1897`), приветствие про покупку в `BotCallbackHandler` FAQ (`:115-148`).
  Готовые тексты — в §4.
- **Трудоёмкость:** S (только тексты).
- **Риск:** нулевой. Начни с этого прямо сегодня — код не трогается, только строки.

#### P0.4 — Превратить рекламу и авто-даунгрейд в умные апселлы
- **Что:** (а) когда премиум-модель недоступна — не сухая приписка, а сообщение
  с кнопками «⚡ Безлимит за N⭐» и «💰 Пополнить баланс». (б) Рекламный слот в
  free-tier по умолчанию использовать под **самопродажу** («📣 Надоела реклама и
  лимиты? Открой премиум → /buy»), а не только под внешние баннеры.
- **Зачем (принцип: продавай в момент боли).** Точка максимальной готовности купить —
  ровно тогда, когда человек упёрся в ограничение. Сейчас этот момент почти не
  используется.
- **Где в коде:** оффер в `processContent` (`:151-157`); `maybeServeAd`
  (`GenerationCoordinator:53`) + дефолтная кампания-самопродажа через `AdCampaign`
  (`Domain/Chat/AdCampaign.swift`) / `nextAdToShow`.
- **Трудоёмкость:** S.
- **Риск:** низкий. Не спамь — Telegram банит навязчивость, и юзеры уходят.

### P1 — следующий заход (масштабирование воронки)

#### P1.1 — Реферальная программа для обычных юзеров
- **Что:** «Пригласи друга → вы оба получаете +$1 на баланс (или +3 дня премиума),
  когда друг напишет первое сообщение». Персональная ссылка `t.me/bot?start=ref_<userID>`.
- **Зачем (принцип: самый дешёвый трафик — от своих юзеров).** Реферал с
  двусторонней наградой — классический вирусный цикл. У тебя **уже есть** движок
  диплинков `/start <payload>` (`handleStart:333`) и балансы — надо добавить ветку
  `ref_` и начисление обеим сторонам (с защитой от накрутки: награда после первого
  реального сообщения приглашённого, один раз на пару).
- **Где в коде:** `handleStart` payload-роутинг (`:336-341`), новое хранилище
  «кто кого привёл» + `creditBalance`. Не путать с админскими `inv_`-инвайтами.
- **Трудоёмкость:** M. **Риск:** средний (антифрод — обязательно).

#### P1.2 — Напоминания: перед истечением и winback после
- **Что:** за 3 дня до конца подписки — «подписка заканчивается ДД.ММ, продли со
  скидкой». После истечения (день +1, +7) — «вернись, вот −30% на возврат».
- **Зачем (принцип: удержать в разы дешевле, чем привлечь; loss-framing).**
  Продление — самая маржинальная выручка. Сейчас подписка истекает молча, чаты просто
  теряют платные модели. Один фоновый цикл вернёт заметную долю оттока.
- **Где в коде:** новый фоновый таск рядом с `runPersistenceNotifyLoop` (см. §14
  CLAUDE.md), проходит тенантов, сравнивает `paidUntil` с now, шлёт сообщение
  (идемпотентно — помечать «напоминание отправлено», чтобы не спамить).
- **Трудоёмкость:** M. **Риск:** низкий.

#### P1.3 — Онбординг с мгновенной ценностью
- **Что:** в `/start` добавить 2–3 кнопки-примера («✍️ Напиши пост про…»,
  «💡 Объясни простыми словами…», «🌍 Переведи текст»), которые подставляют готовый
  запрос. Человек за один тап видит результат = «ага-момент».
- **Зачем (принцип: time-to-value).** В Telegram выигрывает тот, у кого путь до
  «вау» короче. Пустой чат после /start — частая точка отвала.
- **Где в коде:** `sendStartGreeting` (`:446`) — добавить кнопки; обработка —
  либо `switch_inline_query`, либо callback, кладущий текст в чат.
- **Трудоёмкость:** S–M. **Риск:** низкий.

#### P1.4 — Воронка-аналитика для владельца
- **Что:** считать переходы: `/start` → первое сообщение → упёрся в премиум-потолок →
  открыл paywall → отправлен инвойс → оплатил → продлил → отвалился. Показать в
  супер-меню и в `/metrics`.
- **Зачем (принцип: нельзя улучшить то, что не измеряешь).** Без воронки ты чинишь
  вслепую. С ней видно, какой стык течёт, и туда бьёшь.
- **Где в коде:** расширить `RuntimeMetrics`/`MetricName` (§11 CLAUDE.md) новыми
  счётчиками + отдельная страница супер-меню.
- **Трудоёмкость:** M. **Риск:** низкий.

### P2 — когда воронка уже приносит деньги (оптимизация)

- **P2.1 Годовой тариф / скидка за срок.** Анкер к месячному + предоплаченный LTV.
  `subscriptionDays` (`ChatContextStore:273`) сейчас константа 30 — понадобится
  несколько вариантов длительности.
- **P2.2 A/B цены.** Цена уже меняется вживую из супер-меню без передеплоя — используй
  это: меняй раз в 1–2 недели, смотри конверсию из P1.4.
- **P2.3 Промокоды / стартовая скидка.** «−50% на первую подписку» новичкам.
- **P2.4 Полировка оплаты.** Stars — герой (2 тапа, без карты), крипта/карта —
  вторичны. Убедись, что Stars всегда первым и максимально гладко.
- **P2.5 Соц-доказательство.** «Уже помогаю N пользователям» — **только с реальными
  числами**, не выдумывать. Добавить, когда наберётся аудитория.

## 4. Готовые тексты (копирайтинг, paste-ready)

> Тон: коротко, на «ты» или на «вы» единообразно, выгода в первой строке, один
> понятный призыв к действию. Telegram-разметка — HTML (§17 CLAUDE.md).

### 4.1 Paywall (замена `renderBuy` для персоны A)
```
⚡ Премиум-доступ

Что получаешь:
• Лучшие модели — GPT, Claude, Gemini (умнее и точнее бесплатных)
• Без дневных лимитов — пиши сколько нужно
• Без рекламы
• Память и настройки под тебя

Всего <b>{price}</b> на 30 дней — меньше, чем чашка кофе в неделю.

[💫 Оплатить {price_stars} ⭐]
[🪙 Криптой]   [💳 Картой]
— — —
Не готов на месяц? Пополни баланс и плати только за то, что пишешь:
[$2]  [$5]  [$10]
```

### 4.2 Оффер при исчерпании дневного премиума (P0.2)
```
⚡ Премиум на сегодня закончился (5/5 сообщений).

Продолжай бесплатно — или сними лимит навсегда:
[⚡ Открыть безлимит]  [💰 Пополнить баланс]
```

### 4.3 Реклама-самопродажа (дефолтная кампания, P0.4)
```
📣 Надоела реклама и лимиты?
Премиум-доступ убирает и то, и другое → /buy
```

### 4.4 Напоминание перед истечением (P1.2)
```
⏳ Подписка заканчивается {date}.

Продли сейчас, чтобы не потерять платные модели и настройки:
```

## 5. Ценообразование — конкретные числа и логика

> Цены Stars и способы оплаты меняются вживую из супер-меню (§13 CLAUDE.md) — это
> твоё преимущество: экспериментируй без передеплоя.

**Стартовая раскладка (потом крутить по данным):**

| Продукт | Что даёт | Ориентир цены | Логика |
|---|---|---|---|
| Free | Free-модели без лимита + реклама + 5 премиум-сообщений/день | 0 | Удержание + вкус премиума. |
| Кредиты (pay-as-you-go) | Любые модели по факту, наценка 30% | Пакеты $2 / $5 / $10 | Низкий порог первой оплаты. |
| Премиум 30 дней | Все модели, без лимитов, без рекламы | ~**299–499 ⭐** (~$5–8) | Основной продукт. Начни с 299, подними если берут легко. |
| Годовой (P2) | То же, на год | ~10× месячного (2 мес. в подарок) | Анкер + предоплаченный LTV. |

**Психология цены (применяй везде):**
- **«Charm pricing»:** 299, а не 300. Мелочь, но работает.
- **Анкоринг:** всегда показывай, с чем сравнить (кофе / годовой тариф рядом).
- **Три опции, не одна:** «Кредиты / Месяц / Год» — средняя выглядит разумным
  выбором (эффект компромисса).
- **Стоимость provider'а у тебя ~центы за ответ** (видно в `/inspect`, `spentRealUsd`),
  наценка 30% уже зашита в `priceMultiplier()`. То есть маржа положительная на
  каждом уровне — можно смело давать дневной премиум-вкус, он почти ничего не стоит.
- **Про Stars:** самый гладкий метод (2 тапа, без карты), но у платформы есть своя
  комиссия в курсе Stars. Крипта/карта дают больше маржи, но выше трение. Для
  конверсии **Stars — главный путь**, остальное — опции.

## 6. Метрики: что мерить и какие числа считать нормой

Инструментировать в рамках P1.4. Минимальный набор:

| Метрика | Как считать | Ориентир |
|---|---|---|
| Активация | доля нажавших /start, отправивших ≥1 сообщение | >60% |
| Удержание D1 / D7 | вернулись на след. день / через неделю | D1 >25%, D7 >10% |
| Достигли потолка | доля активных, исчерпавших дневной премиум | чем выше, тем горячее спрос |
| Открыли paywall | доля дошедших до страницы покупки | — |
| Конверсия free→paid | купили / активные бесплатные | 2–5% |
| Renewal rate | продлили / у кого истекла | >40% |
| Отток | истекли и не вернулись за 14 дней | минимизировать |
| ARPU / LTV | выручка на юзера; LTV ≈ чек × число продлений | растить |

Правило: смотри **один стык за раз**, чини, меряй, повторяй. Не пытайся
оптимизировать всё сразу.

## 8. Технические напоминания при реализации (из §17 CLAUDE.md)

- Любая новая изменяемая сущность в `ChatContextStore` (счётчики премиума, рефералы,
  флаги напоминаний) обязана: помечать dirty-set при мутации + экспорт/импорт в
  `ChatContextStore+Persistence.swift`. Иначе не сохранится. *Исключение:* дневной
  счётчик премиума можно держать in-memory (обнуление при рестарте некритично).
- Все цены пользователю — только через `priceMultiplier()` (`billedCost`, футер,
  списания). Не показывать сырой `totalCost`.
- Платежи — `flushNow()`, идемпотентность обязательна (charge_id для Stars/карты,
  tx-хеши для крипты). Новые payload'ы (кредиты, рефералы) — тоже дедуплицировать.
- Вывод — HTML (`TelegramHTMLFormatter`), не Markdown.
- Не спамить: Telegram наказывает за навязчивость. Апселлы — по делу и в момент боли,
  напоминания — с частотным ограничением.
